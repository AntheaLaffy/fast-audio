# CPU backward execution isolation experiment

## Mechanism and fixed scope

The completed [row-traversal experiment](cpu-backward-traversal-results-v1.md)
improves its primary audio regimes but leaves the tiny-case guard unresolved.
Its selected binary has larger shared backward entries and stack reservations.
That observation motivates code isolation; it does not establish causality.

Declaration `cd9ad8a` precedes implementation. The original
[v1 protocol](../benchmarks/protocols/cpu-backward-isolation-v1.json) was never run:
interface inspection found the frozen control caps each worker at six measured
blocks. The [v2 correction](../benchmarks/protocols/cpu-backward-isolation-v2.json),
declared before any timing or performance inspection, retains all six original
blocks and increases only independent confirmation contexts from five to twelve.
It supersedes the infeasible 32-block provision without changing the candidate
mechanism, control, primary, guards or budget. Preserve v1 as an unexecuted declaration.

Keep the original scalar execution bodies and dispatch payloads of at least
sixteen FP32 elements to separate, non-inlined coalesced-row bodies. Apply this
only to CPU pointwise Copy VJPs and reduction adjoints. Keep local formulas,
ordered contractions, public API, prepared metadata and explicit resources.
No forward, precision, vendor, CUDA or application change belongs to this trial.

Retain original control producer `3b6635754637ca81e897e6431ae88695b8c51496`
and executable `121f8931a976d349e315d6b4f74be7f4330473fba25f43338ab6c4c4b5cbcef5`.
This is a new implementation intervention with its own fixed budget, not more
confirmation for the completed traversal candidate. The original twelve cases,
worker windows, strict FP32, i5-13420H CPU 0, one MKL thread, Rust compiler and
release flags remain unchanged. No baseline reset or new Torch timing is used.

## Admission, precision and decision

Allow one source candidate and one full screen, with no revision or screen retry.
Before timing admission, require full portable/Intel debug/release and CUDA
functional regressions, targeted signed-layout Miri, existing independent local/
composed references, exact full control/candidate payloads, identical explicit
resources and zero warmed Rust allocations. Validate and retain eight independent
updates, every warmed window's evolving FP64/eager control and exact reset/repeat.

Use the original six balanced paired blocks for every case. The previous
five-context tiny evidence cannot exclude the five-percent slowdown margin.
More fresh contexts are fixed now to improve resolution at the level that varied. Inner training
steps and blocks are not independent context replicates. Longer sampling still
does not guarantee adequate precision, and unresolved evidence retains control.

Screen admission requires primary point speedup at least 1.10 and all twelve
case point speedups at least `1/1.05`. Freeze the exact candidate, collector,
assessment rules and selection before exactly twelve fresh confirmation contexts.
Rotate/reverse catalogue order and alternate pair/startup order by context,
catalogue index and block, retaining every observation. Run no concurrent local
compilation or benchmark work during these measurements.

Each case/context effect is the mean of its paired log control/candidate wall
latency ratios. The primary context effect is the equal-weight mean across
`wave-multichannel`, `wave-long`, `spectrum-medium` and `spectrum-large`.
Across the twelve fresh contexts, compute one-sided df=11 Student-t lower bounds
with `alpha=0.05/13`. The primary bound must reach `log(1.10)`; all twelve guard
bounds must reach `-log(1.05)`, after all hard gates pass.

These model-based bounds assume approximately normal independent context effects
on this pinned host. Error control covers this one frozen candidate's thirteen
bounds, not earlier or unlimited later trials, deployment populations or unseen
inputs. No distribution-free or framework-wide performance claim follows.

The measurement/diagnostic budget is 2400 seconds, at most 420 seconds per context.
No extra confirmation, removed slow block, changed estimand, looser guard or
promotion based on a favorable pooled median is allowed. An invalid or incomplete
context is preserved and stops this campaign; do not replace it after inspection.

## Diagnostics and preservation

Inspect symbols/prologues read-only for the original control, archived row candidate
and isolated binary. If a new result has an unexplained residual, allow at most
one separate bounded waveform profile pair within the same budget. Code size and
sample shares explain hypotheses; the complete-step outcome decides acceptance.

Preserve the declaration commit, source/build/executable identities, immutable
collector copies, all request/reply/payload artifacts, actual run order, environment,
functional checks, failures and independently recomputable decision. The completed
row-traversal evidence remains unchanged. Rejected or unresolved isolation restores
the scalar control. NVIDIA functional checks do not qualify NVIDIA performance.

## Completed screening outcome

The [complete results](cpu-backward-isolation-results-v1.md) preserve the corrected
declaration, exact source/binary, full functional and bit/resource checks, one preflight
and the sole screen. Primary point speedup is 1.5376, but `dense-tiny` and `wave-tiny`
fail the unchanged point guard. No candidate is selected and no confirmation is run.
The scalar control source is restored. This family receives no revision, retry or
extra observations, and its unconfirmed gains do not qualify broader performance.
